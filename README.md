
# Secret-Vault

<div dir="rtl" align="right">

**מערכת לשיתוף קבצים מוצפנים באמצעות מנגנון אישור קבוצתי (Threshold).**

Secret-Vault הוא פרויקט, המבוסס על ארכיטקטורת לקוח–שרת בפייתון. בעל קובץ בוחר קבוצת נמענים ואת מספר האישורים הדרוש לפתיחתו. למשל, אם נבחרו חמישה נמענים והסף הוא שלושה, הקובץ נפתח רק לאחר ששלושה נמענים אישרו. מרגע הפתיחה נוצר חלון הורדה של **60 שניות** למשתמשים שאישרו, ובסיומו השרת מוחק את הקובץ המוצפן והנתונים הקשורים אליו.

ההצפנה והפענוח נעשים בצד הלקוח. השרת מאחסן קובץ מוצפן ו־Shares מוצפנים, ולא מקבל את הקובץ הגלוי או את מפתח ה־AES עצמו.

## כיצד המערכת עובדת?

1. **רישום משתמש:** הלקוח יוצר זוג מפתחות RSA-4096. המפתח הציבורי נשמר בשרת והמפתח הפרטי נשמר במחשב המשתמש, כשהוא מוצפן בסיסמה.
2. **העלאה:** בעל הקובץ בוחר 2–16 נמענים ואת מספר האישורים הנדרש (Threshold).
3. **הצפנת הקובץ:** הלקוח מצפין את תוכן הקובץ באמצעות AES-256-GCM.
4. **חלוקת מפתח:** הלקוח מפצל את מפתח ה־AES ל־Shares באמצעות Shamir Secret Sharing, כך שרק מספר Shares העומד בסף מאפשר לשחזר אותו.
5. **הצפנת Shares:** כל Share מוצפן בנפרד באמצעות RSA-OAEP/SHA-256 עבור המפתח הציבורי של הנמען המתאים. לשרת נשלחים תוכן הקובץ המוצפן, שם הקובץ, ה־Threshold ופרטי הנמענים עם ה־Shares המוצפנים — **לא הנתיב המקומי של הקובץ**.
6. **אישור:** נמען שמאשר מפענח את ה־Share שלו עם המפתח הפרטי שלו, ומצפין אותו מחדש עבור **כל אחד מהנמענים**. השרת שומר את התרומות המוצפנות ומסמן את האישור כפעיל.
7. **פתיחה:** כאשר מתקבל מספר האישורים הנדרש, השרת שומר את זמן הפתיחה ונועל את מצב האישורים. ניתן לבטל אישור רק לפני הפתיחה.
8. **הורדה:** במשך 60 שניות יכולים המשתמשים שאישרו לבקש להוריד. רק בעת בקשת ההורדה השרת שולח את הקובץ המוצפן ומספר מספיק של Shares שמוצפנים עבור הנמען. הלקוח מפענח את ה־Shares, משחזר את מפתח ה־AES ומפענח את הקובץ אצלו.
9. **תפוגה:** עם סיום חלון ההורדה השרת מסיר את רשומת הקובץ, ה־Shares ואת הקובץ המוצפן שנשמר אצלו.

**הערה:** אישור והורדה הן פעולות נפרדות. האישור אינו גורם להורדה אוטומטית.

## טכנולוגיות

| טכנולוגיה | שימוש בפרויקט |
| --- | --- |
| Python | שרת, לקוח, לוגיקה וקריפטוגרפיה |
| TCP + TLS 1.3 | תקשורת מאובטחת בין הלקוחות לשרת |
| JSON + 4-byte length prefix | פורמט ומסגור הודעות בפרוטוקול |
| SQLite | חשבונות, מטא־דאטה, אישורים ו־Shares מוצפנים |
| AES-256-GCM | הצפנת קבצים ואימות שלמותם |
| RSA-4096 OAEP/SHA-256 | הצפנת Shares למפתחות ציבוריים |
| Shamir Secret Sharing | חלוקת מפתח AES ושחזורו מסף Shares |
| Argon2 | גיבוב סיסמאות המשתמשים בשרת |

## מבנה הפרויקט

- `client/client.py` — ממשק שורת הפקודה (CLI).
- `client/vault_client.py` — פעולות הלקוח, תקשורת מול השרת, אימות מפתחות ואישור Shares.
- `client/file_manager.py` ו־`client/crypto/` — הצפנה, פענוח וחלוקת מפתחות.
- `common/protocol.py` — הודעות JSON מעל TCP עם קידומת אורך של ארבעה בתים.
- `server/server.py` — שרת TLS, טיפול בלקוחות באמצעות Threads וניקוי קבצים שפג תוקפם.
- `server/handlers.py` — טיפול בבקשות והפעלת פעולות השרת.
- `server/file_handler.py` — קליטת הקובץ המוצפן ושמירתו בדיסק.
- `server/database.py` — פעולות SQLite, אישורים, הרשאות ומחזור חיי הקבצים.


## התקנה (Windows / PowerShell)

נדרשים Git ו־Python 3.12. מתוך PowerShell:

</div>

```powershell
git clone https://github.com/arielushka/Secret_Vault.git Secret_Vault
Set-Location Secret_Vault
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install argon2-cffi cryptography shamir-mnemonic
```

### יצירת תעודת TLS במחשב השרת

יש ליצור תעודת שרת ומפתח באמצעות OpenSSL. החליפו את כתובת ה־IP בדוגמה בכתובת מחשב השרת ברשת המקומית.

</div>

```powershell
openssl req -x509 -newkey rsa:2048 -nodes -keyout server.key -out server.crt -days 365 -subj "/CN=192.168.1.20" -addext "subjectAltName=DNS:localhost,IP:127.0.0.1,IP:192.168.1.20"
```

<div dir="rtl" align="right">

**אבטחת תעודות:** את `server.key` משאירים במחשב השרת בלבד. ללקוחות מעבירים את `server.crt` בערוץ אמין. כתובת החיבור חייבת להופיע בשדה SAN של התעודה.

### הפעלת השרת

</div>

```powershell
python -m server.server
```

### הפעלת הלקוח

בחלון PowerShell או במחשב לקוח אחר:

</div>

```powershell
$env:SECRET_VAULT_HOST = "192.168.1.20"
$env:SECRET_VAULT_PORT = "5000"
python -m client.client
```

<div dir="rtl" align="right">

השרת מאזין כברירת מחדל ב־`0.0.0.0:5000`. יש לאפשר גישה לפורט 5000 בחומת האש **רק מהרשת הפרטית המהימנה**. אין לחשוף את הפורט ישירות לאינטרנט.

## מפתחות ואימות זהות

לפני הצפנת Share למפתח ציבורי של משתמש אחר, הלקוח מחשב את טביעת האצבע (Fingerprint) שלו. בפעם הראשונה יש להשוות אותה מול טביעת האצבע שהתקבלה מאותו משתמש בערוץ עצמאי ואמין. לאחר אימות היא נשמרת בקובץ `~/.secret_vault/trusted_keys.json`, כדי לזהות שינויים בלתי צפויים במפתח בהמשך.

המפתח הפרטי של כל משתמש נשמר מוצפן בסיסמה בתיקייה `~/.secret_vault/keys`. ניתן לשנות מיקום זה באמצעות משתנה הסביבה `SECRET_VAULT_KEY_DIR`.

## מגבלות אבטחה

- **המערכת אינה עמידה במלואה בפני שרת זדוני שמשתף פעולה עם נמען שלא אישר.** מכיוון שהמאשרים מצפינים כל Share עבור כלל הנמענים, שרת זדוני יכול להעביר לנמען כזה מספיק Shares שמוצפנים עבורו, והוא יוכל לשחזר את מפתח ה־AES.
- השרת יכול לשמור עותקים של מידע מוצפן לפני מחיקתו. חלון 60 השניות הוא כלל הרשאות ומחיקה בצד השרת, לא הבטחה למחיקה קריפטוגרפית של כל עותק.
- משתמש שכבר הוריד ופענח את הקובץ יכול לשמור אותו לאחר תום החלון.
- טביעת אצבע שמגיעה רק מהשרת אינה מוכיחה זהות; חובה להשוותה בערוץ אמין ונפרד בפעם הראשונה.
- אובדן המפתח הפרטי או הסיסמה עלול למנוע פענוח Shares.
- מגבלת ההעלאה בצד השרת היא 10 MiB של תוכן מוצפן; מגבלת הודעת הפרוטוקול היא 16 MiB.

הפרויקט פותח למטרות לימוד ומיועד להרצה בסביבה פרטית ומבוקרת.
