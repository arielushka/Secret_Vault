# Secret-Vault

Secret-Vault היא תוכנת CLI לשיתוף קבצים מוצפנים. בעל הקובץ בוחר 2–16 משתמשים מורשים וסף אישורים. הקובץ, המפתח הפרטי ושחזור המפתח נשארים בצד הלקוח; השרת מנהל חשבונות, הרשאות וחומר מוצפן.

## איך השיתוף עובד

1. הלקוח מצפין קבצים חדשים עם AES-128-GCM דרך PyCryptodome. השרת מקבל את ה־Nonce ואת הטקסט המוצפן, לא את מפתח AES.
2. הלקוח מחלק את מפתח AES ל־Shares באמצעות Shamir. הסף חייב להיות לפחות 2 ולא גדול ממספר הנמענים.
3. כל Share מוצפן עם RSA-4096 OAEP/SHA-256 למפתח הציבורי של המשתמש שלו.
4. השרת שומר את הקובץ המוצפן ואת ה־Shares המוצפנים.
5. משתמש מורשה יכול להפעיל את האישור שלו. הלקוח שלו מפענח את ה־Share האישי ומצפין אותו בנפרד עבור כל משתמש מורשה.
6. השרת בודק שהלקוח שלח Share מוצפן לכל מורשה בדיוק פעם אחת, שומר את העותקים המוצפנים ומסמן את האישור כפעיל.
7. אין מגבלת זמן לאישור לפני פתיחת הקובץ. כשמספר האישורים מגיע ל־Threshold, הקובץ נפתח.
8. מרגע הפתיחה רק המשתמשים שאישרו יכולים לראות את פרטי הקובץ ולהוריד אותו. לאחר 60 שניות השרת מוחק את הקובץ, ה־Shares וכל המידע הקשור אליו.
9. כל Share שאושר מוצפן למשתמשים המורשים, ופענוח ה־Shares ושחזור מפתח AES נעשים במחשב המשתמש שאישר.

ביטול אישור אפשרי לפני פתיחת הקובץ. לאחר שהקובץ נפתח, רשימת המאשרים נעולה עד למחיקה האוטומטית. משתמש שקיבל קובץ מפוענח יכול לשמור או להעביר אותו.

## הורדה והתקנה

הורידו את הפרויקט המלא בכל מחשב שבו תריצו את התוכנה. נדרשים Git, Python 3.12 ו־OpenSSL ליצירת תעודת TLS.

```powershell
git clone https://github.com/arielushka/Secret_Vault.git Secret_Vault
Set-Location Secret_Vault
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

אם PowerShell חוסם הפעלת סביבה וירטואלית, הריצו בחלון הנוכחי `Set-ExecutionPolicy -Scope Process Bypass` ואז הפעילו שוב את פקודת `Activate.ps1`.

## הפעלה

### 1. יצירת תעודת TLS בשרת

במחשב שישמש כשרת, מצאו את כתובת ה־IPv4 שלו ברשת הפרטית. מתוך תיקיית הפרויקט צרו תעודה ומפתח. החליפו את `192.168.1.20` בכתובת השרת שלכם:

```powershell
openssl req -x509 -newkey rsa:2048 -nodes -keyout server.key -out server.crt -days 365 -subj "/CN=192.168.1.20" -addext "subjectAltName=DNS:localhost,IP:127.0.0.1,IP:192.168.1.20"
```

השאירו את `server.key` במחשב השרת בלבד. העתיקו את `server.crt` לכל מחשב לקוח, אל תיקיית הפרויקט. הכתובת שבה הלקוח משתמש חייבת להופיע בתעודה. אין לשתף או להעלות את `server.key`.

### 2. הפעלת השרת

בחלון PowerShell אחד, מתוך תיקיית הפרויקט ובסביבה הווירטואלית הפעילה:

```powershell
python -m server.server
```

השרת מאזין בפורט `5000`. במחשב השרת, פתחו PowerShell כמנהל מערכת והוסיפו כלל חומת אש שמאפשר TCP/5000 רק מרשת מקומית בפרופיל Private:

```powershell
New-NetFirewallRule -DisplayName "Secret Vault TCP 5000" -Direction Inbound -Protocol TCP -LocalPort 5000 -Action Allow -Profile Private -RemoteAddress LocalSubnet
```

בדקו שהרשת המהימנה מוגדרת כ־Private באמצעות `Get-NetConnectionProfile`. את כלל חומת האש יוצרים רק במחשב השרת.

### 3. הפעלת לקוח

בחלון PowerShell נוסף, מתוך תיקיית הפרויקט ובסביבה הווירטואלית הפעילה, הגדירו את כתובת השרת והפעילו את הלקוח:

```powershell
$env:SECRET_VAULT_HOST = "192.168.1.20"
$env:SECRET_VAULT_PORT = "5000"
python -m client.client
```

באותו מחשב אפשר להשתמש ב־`127.0.0.1` במקום כתובת השרת. כדי להפעיל לקוחות נוספים, פתחו חלון נוסף או הריצו את אותן פקודות במחשב נוסף שבו התקנתם את הפרויקט המלא והעתקתם אליו את `server.crt`.

בהפעלה הראשונה בחרו `Register` כדי ליצור משתמש; בהפעלות הבאות בחרו `Login`. תיקיית מסד הנתונים וקובצי ההעלאה נוצרים אוטומטית בשרת. מפתחות RSA פרטיים נוצרים ונשמרים באופן מקומי אצל כל משתמש.

## מפתחות פרטיים

המפתח הפרטי נשמר במחשב המשתמש בקובץ מוצפן בסיסמה, תחת `~/.secret_vault/keys` (ב־Windows: בתיקיית המשתמש). אפשר לבחור תיקייה אחרת בעזרת משתנה הסביבה `SECRET_VAULT_KEY_DIR`. השרת שומר מפתחות ציבוריים בלבד.

## מגבלות

- השרת מאזין ברשת ב־TCP/5000 ומשתמש ב־TLS 1.3. השימוש מיועד לרשת פרטית מהימנה בלבד; יש להגביל את חומת האש ואין לחשוף את הפורט לאינטרנט.
- מגבלת העלאה בצד השרת היא 10 MiB לקובץ מוצפן; מגבלת הודעת הפרוטוקול היא 16 MiB.
- מרגע שה־Threshold הושג, הקובץ זמין רק למאשרים למשך 60 שניות ואז נמחק מהשרת. עותק שכבר הורד ופוענח יכול להישמר או להישלח הלאה.
- שרת זדוני יכול למנוע שירות או לשמור נתונים ישנים. ביטול אישור אינו מחיקה קריפטוגרפית.
- אם אובדים קובץ המפתח הפרטי המקומי או הסיסמה שלו, אי אפשר לפענח את ה־Shares של המשתמש.
